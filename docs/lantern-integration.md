# Recovered Lantern integration

The user supplied 13 recovered Lantern files from their InVideo build. Originals remain at /workspace/recovery/lantern. This is a partial source recovery, not InVideo's internal source code.

Merged components:
- packages/agent/src/index.ts -> lib/editor/production-graph.ts: intent classification, task graph and readiness helper. Missing upstream types were reconstructed locally. Uses Web Crypto rather than Node Crypto for browser compatibility. Specific music-video/short-film intents take precedence over generic phrases. Assembly depends on missing-input stages, existing scripts no longer reference an absent script node, and rendering follows revision. These are planning dependencies, not a complete workflow executor.
- Orchestrator displays this graph locally and the server provides it as a checklist to the existing bounded edit-agent tool loop. The existing edit approval, provider allowances and explicit generation/export controls remain authoritative.
- packages/storage/src/index.ts -> lib/object-store.ts: recovered ObjectStore contract with R2 implementation replacing Node filesystem/S3 SDK imports. Saved project-context reads now use this adapter. Media URLs require the existing owner authentication; they are not public URLs for external providers. Added object-key validation. Existing CAS workspace writes retain their original implementation to preserve conflict handling.

The root pnpm/Turbo/Docker configs and package-specific configs belong to a separate Hono/Postgres/Redis/Next monorepo. They are preserved as recovered originals, not layered over Codex Studio's working Sites build. Most Lantern application modules remain missing. No standalone Lantern backend, stock provider, new generation model or autonomous end-to-end rendering is claimed by this merge.

## Batch 1 integration
The full recovered shared contracts now live in lib/lantern/types.ts; the production graph imports AgentGraph, AgentNode and Craft from those originals instead of reconstructed types. Recovered provider contracts live in lib/lantern/providers/types.ts. ModelRouter is adapted for explicit provider selection, aspect/resolution/duration/reference/identity/budget filtering and development-only mock opt-in. It does not silently switch providers or retry submissions. The existing generation POST validates the requested provider through this router before recording/submitting a job; actual vendor requests, encrypted connections and idempotency remain in the existing job implementation.

The recovered mock and live stubs are retained in the independent Lantern export only. Stub model names and fabricated credit estimates are not promoted into production models or billing. The independent ZIP contains only recovered project files, without Codex Studio additions, chat exports or recovery notes. It remains incomplete until missing modules and package manifests arrive.

## Batch 2 integration and review
Recovered config, queue, credits, auth and observability modules; storage is a duplicate of the earlier original. The unchanged structured logger is imported into the existing server error-response helper. Request failures now emit service, status and error class, with no request bodies, keys, user data or raw error messages logged by this integration. Logger regression test covers levels, child fields and structured output.

Full Node/Postgres environment schema is not loaded into the Cloudflare runtime. BullMQ/Ioredis requires a separate compatible worker host; MemoryQueue is non-durable and does not handle handler failures. The original credit ledger has non-atomic reserve/grant/release operations, no duplicate-release protection and no actual-cost reconciliation; it is preserved but not enabled as production billing. The original development JWT implementation lacks expiration enforcement and createAuth always returns DevJwtAuth, including when configured for Clerk; it does not replace the existing native owner authentication. These source modules remain intact in the separate original-source ZIP for review with the remaining database/worker code.

## Batch 3 integration
Recovered database index/client/schema/seed/Drizzle config and editor helpers; agent source matched the earlier original exactly. The original Postgres database tree is preserved in the independent ZIP, not applied over the active D1 schema. No seed grants or workspace membership changes were executed.

Browser-compatible timeline helpers are in lib/lantern/editor.ts, with appendClip corrected to append once to an unlocked matching track after the latest end time. lib/lantern/project-export.ts uses those helpers for Project menu -> Download Lantern timeline JSON. It maps seconds to milliseconds, preserves source windows with speed, tracks and raw Codex fields, embeds the original source project and lists format limitations. This is a metadata export with media references, not embedded media or a verified standalone import/render path. x/y remain Codex percentage values. The original ffmpegArgs function ignores source trims, speed, audio, captions, transforms, track order and effects; it is preserved in the original-source ZIP but not used as production rendering.

## Batch 4 API adaptation
Recovered API entrypoint/app and health/dev/projects/assets/jobs/timelines routes, unchanged in the independent source ZIP. Existing Sites routing, encrypted connections, owner auth, D1 project revision checks and generation-job submission logic remain authoritative.

Adapted the supplied timeline-read API concept through authenticated GET /api/projects?id=<saved-project-id>&format=lantern. This returns the same Lantern interchange format as the existing browser download plus the saved revision. Stored project data is schema-validated, and missing projects retain the original 404 response. Runtime tests cover saved revision/project preservation and unauthenticated rejection. It is not an exact /v1 drop-in compatibility server.

The original API requires Hono, Postgres, Redis and missing route modules/package manifests. Dev token minting is development-only and is not added to Codex Studio. Original generic job creation lacks atomic reserve/enqueue and robust deduplication; snapshot writes accept unvalidated documents and compute versions without optimistic locking. Asset/job project references need workspace ownership validation and upload bounds; role-specific write checks are absent. These are review items for independent testing, not routes enabled on the published studio.

## Batch 5 adaptation
Recovered all seven remaining Hono routes, unchanged in the independent ZIP. Project-scoped brand kit input now lives in lib/lantern/brand.ts and is editable in Context -> Production workspace. Colors/typeface names and a kit name persist through the existing context revision API and session snapshots, and are automatically supplied to AI editing, production planning and optimization when context is enabled. This is planning guidance, not automatic media styling or font downloads. Tests verify saved brand context reaches model requests and survives session storage. Existing app branding remains blue.

Other original routes are held for integration review: templates currently lists all workspaces without scope filtering; lock readiness does not verify master asset ownership; agent/caption routes do not validate supplied project/asset ownership; billing reports only the development ledger, not vendor balances. Stock's reference-use note is only text, not enforced licensing logic. No new stock licence or true visual identity lock is claimed.
